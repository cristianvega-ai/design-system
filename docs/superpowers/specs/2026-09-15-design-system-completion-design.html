Decisions

Settled before the work starts.

decided

Home: its own repository

The sheet and every source move into ~/Projects/design-system before change 1. The handwritten sheet is under version control from the first commit. The maintainer is the owner of the cristianvega-ai repositories.

decided

Checks come first, on one toolchain

The build and its five checks are change 1, all on Node 24. Style Dictionary 5, the standard token build, writes the tokens; one short script writes the sheet. Both current scripts exit 0 even when they report a problem, so they are replaced by checks that exit 1 and never write a file.

removed

Dark mode

The concept leaves this work entirely. The sheet keeps its statement that version 1 has no app-wide dark mode. The backlog holds it with the trigger: an app must follow system appearance.

removed

Migration table

None. The old names are gone from the sheet. The console aliases stay until a product adopts the system.

decided

Text rules, scoped

The sheet's descriptive text and the spec follow Simplified Technical English with spelled-out acronyms. Code comments use plain language. No script counts words.

deferred

Swift output, symbol names, widget behavior

Each waits in the backlog for a trigger: a native app adopts the system, or a product needs a working composite widget.

Artifacts

What a token is, and what each file does.

A token is one named value: a color, a size, a spacing step, a radius, a shadow, a duration. The name is what a rule on the sheet uses. The value lives in one place, the token file. Change it there, run the build, and every rule that uses the name follows.

1 · in tokens.json · you write this
"fs-ui": {
  "$type": "dimension",
  "$value": "13px",
  "$description": "the console ground"
}

fs-ui is the name. 13 pixels is the value. The description becomes a comment.

the build writes
2 · in the sheet's :root · generated
--fs-ui: 13px; /* the console ground */

The same name and value, as a custom property that any rule in the stylesheet can read.

a rule reads
3 · in a component rule · handwritten
.btn--mini {
  font-size: var(--fs-ui);
}

The rule names the token. It never repeats the number.

on screen
4 · the resultApprove

A mini button at 13 pixels. The same on every ground, and in every product that reads the same names.

A value can point at another token by its path. "signal": { "$value": "{brand.crimson}" } becomes --signal: var(--crimson). One color, several names, one place to change it.

you write it

tokens.json

The list of every named value: colors, type sizes, spacing steps, radii, shadows, durations, focus rings, layers. 158 tokens today, plus the version and the date.

Read by the build and by the contrast check.

Mechanism

How a value travels, and what stops a bad one.

Five steps. A value is typed once. The build copies it into the sheet. The checks read the result and stop a bad one. Nothing in step 4 writes a file.

  1. 1 Type the value once

    In tokens.json: the 158 product tokens, the version, and the date. No other file holds a token value.

    The build also reads icons/, sixteen vector files.

  2. reads
  3. 2 Build

    npm run build: Style Dictionary writes dist/tokens.css, then inject.mjs writes the sheet. It stops on a missing, duplicate, or reversed marker, or a reference to a missing token. Otherwise it writes step 3 and prints each file.

  4. writes between the markers
  5. 3 Five places get written

    Four are inside the sheet. Each sits between two marker comments, and the build replaces only what is between them.

    • The token listinside the sheet's stylesheet, so every rule can read the names/* build:tokens */
    • The printed token listin the Adoption section, for people to read and copy<!-- build:token-block -->
    • The printed ground contractin the Adoption section, copied from the live rules<!-- build:ground-contract -->
    • The icon drawingsat the top of the page, reused by every icon on it<!-- build:icons -->
    • dist/tokens.cssa separate file: the token list alone, for a producta file, not a marker

    Everything else on the sheet is handwritten. The fonts load on their own.

4Check the resultchecks/run.sh · reads only · exits 1 on any failure
  1. 4.1 Testsnode --test for the inject, drift, and contrast scripts. Runs first.
  2. 4.2 InventoryReads the sheet's rules. Fails on a raw pixel or hex with no entry in exceptions.json.
  3. 4.3 ContrastReads tokens.json and resolves references. Fails on a pair under 4.5:1 for text or 3:1 for a boundary.
  4. 4.4 MarkupReads the sheet. Fails on an unbalanced tag.
  5. 4.5 DriftBuilds into a temporary folder. Fails when a region, dist/tokens.css, or the version differs from that build.
5
Exit 0: the change is good. Exit 1: fix it before review.

The tests prove that the checks catch a fault. An edited region, a pair under its limit, and a raw pixel with no exception must each fail.

Order

Three changes. Each one is reviewable on its own.

The checks arrive with the build, so every later change runs against them. Each change updates the sheet, the token file, the checks, and this page together.

  1. Source and checks
    • The repository, with the sheet under version control.
    • The 158 product tokens extracted from the sheet, not redesigned.
    • Style Dictionary and the inject script, valid markers, four regions, dist/tokens.css.
    • Five checks, their unit tests, and exceptions.json with a reason per entry.
    Two builds in a row are identical. Every existing value is preserved. The three intentional faults fail their checks. run.sh exits 0.
  2. Current controls
    • --g-line-control on three grounds, from the ground contract.
    • Native simple controls; real select; labels, hints, and errors linked.
    • Forced states only inside marked examples. No is-* alias for a native state; model-driven classes stay.
    • Composite widgets as static pictures with a keyboard table.
    browser.mjs shows every enabled simple control in the tab order with the ring, and the expected boundary color per state and ground. You approved the before and after. run.sh exits 0.
  3. Assets and documentation
    • Local fonts with separate fallback faces that carry the metrics.
    • One inline icon sprite from icons/.
    • Layer tokens, the overlay table, the naming rule.
    • The completeness audit, the text rules applied, the change log and README for 1.2.0.
    The sheet renders with no network. Generated regions match the build. The audit lists no open item. run.sh exits 0.

Controls

Simple controls become native. Composite widgets stay pictures.

A native element brings its own state, so the sheet keeps no is-* alias for a native state. Model-driven classes such as is-selected stay. A state the sheet cannot enter on its own, such as focus, shows inside a marked example: .input:focus-within, .example[data-state="focus"] .input. Tabs, menus, popover lists, and the palette need keyboard behavior the sheet does not implement. The sheet wraps them as images with a keyboard table beside them.

Fonts

Local files, and a separate fallback face.

  • The weights the sheet uses, as latin woff2 files in fonts/, next to the sheet, so the relative path resolves.
  • Five files come from cristianvega.ai; the rest from the Google Fonts endpoint, one latin file per weight.
  • Each face has font-display: swap. The metric overrides sit on a separate fallback face declared with src: local(), never on the downloaded face.
  • fontTools measures the overrides once in a throwaway environment; the values and the command go into fonts/README.md.
  • The sheet must render with no network.

Icons and audit

One sprite. Every promise resolved.

  • Sixteen files in icons/. The build writes them into the sheet as one inline sprite, so the sheet still opens from disk.
  • The Icons caption drops the promise of a system symbol mapping. The backlog holds it with its trigger.
  • The audit lists every component, size, or behavior the text names with no rule. Each gets a rule and a specimen, a deleted promise, or a backlog entry with a trigger. Deleting an unneeded promise is a valid outcome.
  • Known today: the drawer, the 46-pixel reader toolbar, the tip position, the popover offset, the 840-pixel narrow container, the 48 and 44-pixel document padding, the symbol mapping.

Text rules · sheet and spec only

Short, active, one word per thing.

  • A sentence has one topic and 20 words or fewer.
  • Active voice. Say who does what.
  • One instruction in each sentence. Start with the verb.
  • The same word for the same thing.
  • "Must" for a requirement. "Can" for a possibility. Never "should".
  • No acronym in descriptive text. A class name, a token, or a file extension is not an acronym.
  • A short usage instruction comes before the reference detail.
  • Specimen text does not change. Code comments use plain language. No script counts words.

Backlog · each entry has a trigger

Nothing here is built before its trigger.

  • Dark mode for the app frame · an app must follow system appearance.
  • DesignTokens.swift, one more platform in the build configuration · a native app adopts the system.
  • SF Symbols names for the sixteen icons · a native app adopts the system.
  • Working examples of composite widgets · a product needs one.
  • A published package and product-side checks · a product adopts the system.
  • Continuous integration for run.sh · the repository gets a remote.

Done

The work is done when all of these are true.

  • The repository exists, holds the sheet and the sources, and has the change log for 1.2.0.
  • The token file is the source. The build writes the four regions and tokens.css. drift.mjs passes.
  • Every simple control specimen is a native element with native states, and browser.mjs confirms the tab order and the ring.
  • --g-line-control measures 3:1 or more on all three grounds, and you approved the look.
  • The sheet renders with local fonts and one inline icon sprite, with no network.
  • The layer tokens exist and the overlay table has no empty cell.
  • The naming rule is on the sheet.
  • The completeness audit lists no open item, and the backlog has a trigger per entry.
  • All descriptive text follows the text rules.
  • checks/run.sh exits 0.
